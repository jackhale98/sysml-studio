# SysML Studio audit — 2026-08

Scope: standard conformance, model-development/analysis/modification
practice, and integration with the companion tooling (sysml-core,
tree-sitter-sysml, sysml-domain-libraries). Method: full source review
of `src-tauri/` and `src/` against sysml-core 0.8 and the SysML v2
standard, plus running the bundled demo model through the current CLI
and the OMG pilot implementation (the ecosystem's conformance oracle).

Verdict in one paragraph: the architecture has the right spine — the
model is re-parsed from text (no drifting object graph), parsing is
shared with the CLI, and the simulation surface delegates to sysml-core
correctly — but almost everything above the parser (views, traceability,
completeness, BOM, validation, editing) is a Studio-private
reimplementation that is lower-fidelity than the engines sitting one
crate away, diverges numerically and semantically from the CLI on the
same model, and in three places corrupts or mis-targets the user's
source. The pinned sysml-core is 69 commits (two releases) stale, which
means the app rejects standard-conformant SysML that the rest of the
toolchain accepts, and ships ~12 MB of unnecessary parser tables into
the iOS binary. The demo content itself fails the OMG pilot.

---

## 1. Critical correctness defects (all independent of the version pin)

### 1.1 Span mismatch: every edit targets the wrong line
sysml-core spans are 1-based (`Span::from_node`, model.rs); the frontend
indexes them 0-based (`lines[element.span.start_line]` in
source-editor.ts:324,370,460 and renders `start_line + 1` for display).
Every displayed line number is off by one, `editElement` rewrites the
line after the declaration, and `deleteElement` deletes a shifted
window. The unit tests hand-construct 0-based spans (`makeSpan(0, 1)`),
so they encode the wrong convention as expected behavior.

### 1.2 Import/multi-file concatenation corrupts every span
`open_file` parses a synthetic buffer (imported files prepended to the
active file — parse_commands.rs:55,121; model-store.ts:59-83 does the
same on the frontend) but the editor holds the original file. The
moment any import resolves or a second file is open, all spans are
offsets into a document the user never sees: click-to-source,
diagnostics anchors, edit/delete all land in arbitrary wrong places —
`deleteElement` splices arbitrary line ranges out of the user's file.
Imported elements also inflate stats and duplicate-detection.

### 1.3 Traceability ignores the standard's satisfy/verify semantics
The graph matches satisfy/verify targets by bare-name string equality
against the *containing* element (graph.rs:105-134), discarding the
`by` target the adapter correctly captured. Consequences on canonical
ecosystem models: `satisfy overpressureProtection.minTravel by relief;`
(feature chain) matches nothing; `<'R-BATT-01'>` short names never
resolve; there is no qualified-name resolution and no specialization
closure (satisfying `Derived :> Base` does not satisfy `Base`, which
the CLI resolves and reports "(via specialization)"). The MBSE
dashboard's "UNSATISFIED REQUIREMENTS" panel raises false alarms on
models the CLI traces at 100%. Requirement defs and usages are also
scored identically, inverting standard practice (defs are types).

### 1.4 Two rollup engines that disagree, both unit-blind at the boundary
The BOM tab uses a hand-rolled sum (analysis_commands.rs:79-159): bare
`parse::<f64>()` so `mass = 250 [SI::kg]` contributes 0; multiplicity
`[0..4]` counts as 4 and `*` as 1. The Rollup tab calls the real
`evaluate_rollup` — so the same attribute yields different totals in
adjacent panels — but then drops the engine's `unit` and
`conversion_warnings` fields (analysis_commands.rs:337-346), restoring
exactly the silent-wrong-number failure the engine was built to
prevent. The frontend re-applies multiplicity math on top
(AnalysisView.tsx:244-250).

### 1.5 String-splicing edits can corrupt unrelated text
source-editor.ts renames via unanchored first-occurrence
`line.replace(...)` (renaming `Wheel` corrupts `wheelMass`), inserts
by brace-counting that miscounts braces in comments/strings, mangles
multi-line doc comments, and never re-validates or diffs before
`save_file` does a non-atomic `fs::write`. sysml-core's
`codegen/edit.rs` (byte-accurate spans, overlap-rejecting apply,
`body_end_byte` insertion, rename, unified diff) is entirely unused —
and its `body_end_byte` anchor exists even on the pinned version.

### 1.6 Backend robustness
All 30 Tauri commands run blocking on the IPC thread (no `async`),
including full re-parses; nine analysis commands each re-parse the
whole buffer despite the parsed model sitting in AppState; a panic
caught under `catch_unwind` while holding the model mutex poisons it
permanently (every later command errors until restart); frontend
panels swallow every error with bare `catch { }`, making wrong results
indistinguishable from empty models.

## 2. Standard conformance

### 2.1 The demo model fails the OMG pilot implementation
`SAMPLE_SOURCE` (App.tsx) is rejected by the pilot: fork `then`
continuations are detached from their fork declarations
(`first start then forkBoard; then driverGetIn;` — conformant SysML
requires the `then` successions to directly follow the fork usage).
It also contains a genuine modeling error (a `DrivePort` connected to
a `FuelPort` — today's W006 catches it; the pinned core predates the
check), plus: `verify`/`satisfy` inside part *defs* without `by`;
`allocate SafetyReq to processing;` (allocating a requirement —
requirements are satisfied, not allocated); unitless `Real` throughout
(`passengerCount : Real = 4`); view filters `@SysML::PartDef` /
`@SysML::Part` (standard reflective names are `PartDefinition` /
`PartUsage` — and these filters parse to nothing, so the demo's own
views silently ignore them); `render asTableDiagram` (official Views
library: `asElementTable`); a "trade study" whose alternatives are
plain parts with doc comments (no variant/variation, no objective
expression — nothing for the engine to score).

### 2.2 Generated SysML is nonconformant
source-editor.ts emits `analysis case def` / `verification case def`
(standard: `analysis def` / `verification def` — the app's own output
does not re-parse as the intended kind); `satisfy X;` / `verify X;`
with no `by` clause (untraceable by both Studio and the CLI); unquoted
hyphenated short names (`<SC-100>` — must be `<'SC-100'>`); transition
clause order `first X if g do e then Y` (guard/effect belong in the
transition body after `then`); no quoted-name support anywhere; no way
to author metadata annotations (`@Type { field = value; }`) at all —
the syntax the whole domain-library convention rests on. The test
suite locks the nonconformant forms in as expected output.

### 2.3 Terminology and taxonomy
The def/usage taxonomy and labels are largely correct (no
class/instance language), but SysML v1 vocabulary leaks ("block" kinds
in the view/diagram layer, "Block Definition Diagram" in the README),
`accept_action` exists in the UI but not the backend enum, multiple
supertypes are dropped (`part def A :> B, C` loses `C`), and
connection endpoints display under a "Specializes" label
(ElementDetail.tsx:56 rendering the overloaded field the adapter
stuffs endpoints into).

## 3. Ecosystem integration

What Studio reuses correctly: `parser::parse_file` + `qualify_model`,
`checks::all_checks()` (though it discards spans/suggestions —
diagnostics are unanchored strings), and the whole `sim::*` surface
(constraints, calcs, state machines, action execution, analysis cases,
trade study, what-if, sweep, units). The simulation delegation is a
model of how the rest should work.

What it reimplements or omits (≈9,000 lines of core capability):

| Capability | sysml-core | Studio |
|---|---|---|
| Model-defined views | `view_render` — @TableRendering: row providers (@Fmea, type:, relation:, trace, uncertainty), computed columns, where/sortBy/pivot | view-evaluator.ts: private expose-glob + 40-name kind map; @TableRendering absent; domain-library views (FmeaWorksheet, StackupSummary) silently render as a full-model tree |
| Uncertainty analysis | worst-case / RSS / seeded Monte Carlo + histogram, Pp/Ppk, yields | absent (no FMEA, tolerance, hazard, likelihood anywhere in src/) |
| Requirement closure | traced_requirement_defs (usages, `<ID>`s, specialization, cross-file) | bare string equality (§1.3) |
| Coverage + gates | QualityScore calc, evaluate_gate (QualityGate/TraceGate, fail-closed) | hardcoded weight formula; no gates — a model failing its own declared gate shows green |
| Validation | resolver + embedded stdlib + 16 checks + W017 | hand-rolled 4-rule check with a 9-entry stdlib list — `ISQ::mass` is a false "type not found" |
| Editing | codegen/edit.rs byte-accurate edits + diff | line splicing (§1.5) |
| Imports | resolver::Project (root namespace, aliases, stdlib) | same-directory filename guess from a line-prefix scan; `import ISQ::*` looks for `./ISQ.sysml` |

Architectural note for the upgrade: W017 (`check_value_constraints`) is
not part of `all_checks()` — it takes `&[Model]` project-wide — so a
version bump alone will not surface it; it needs an explicit call.

## 4. Staleness (pin: sysml-core 0.5.0 @ 441403f, 2026-03-30; current 0.8.0, 69 commits ahead)

Ranked by user impact:

1. **The old grammar rejects standard SysML** that rounds 1–5 fixed
   from OMG-authored models (then-targets with bodies, perform values,
   render bodies, allocate `::>` bindings, action assign, typed flow
   payloads, message payloads). Studio shows valid models as parse
   errors and drops the surrounding elements from every panel.
2. **`:>> name = value;` is invisible** (no standalone_redefines
   extraction) — the domain-library idiom for dimension values produces
   no element: BOM contributes 0, rollup targets missing, silently
   wrong numbers.
3. **No quoted-name normalization** — `'Air Frame'` never matches
   `Air Frame` anywhere in Studio's string-equality identity layer, so
   containment/edges/traceability silently drop for models in official
   corpus style.
4. **No metadata annotations** — `@Fmea { severity = 8; }` invisible.
5. **Validation underreports**: missing W012–W016 (+W017, see above).
6. Cross-file satisfy/verify resolution absent (false W002/W003).
7. Rollup units absent on the pin (and dropped at the boundary anyway).
8. `Usage.doc` unavailable — requirement usage text is blank.
9. Parallel state regions simulate wrong (single-region trace).
10. Action-flow anchor semantics predate the rewrite — different
    activity structure than `sysml diagram afv` / `simulate` today.
11. Variants invisible (`variant`/`variation`, variant-aware rollup).
12. **iOS binary size**: old parser.c is 52.0 MB vs 39.6 MB now (−24%,
    STATE_COUNT −29%) — the largest single contributor to app size on
    a TestFlight-distributed app.

Every API Studio calls still exists at 0.8 with identical signatures
(verified symbol-by-symbol); the deleted modules are ones Studio never
imported. The upgrade is near-free on API surface. Pin a tag
(`tag = "v0.8.0"`), not `branch = "main"`.

## 5. Tests

20 unit tests, all over hand-constructed element vectors. Zero tests
parse a real `.sysml` file; no `src-tauri/tests/`; `tempfile` is
declared and unused. diagram_commands.rs (1,491 lines): 0 tests.
`convert_model`, `resolve_parents`, `convert_span`, `open_file`,
`resolve_sibling_imports` — all untested; each of §1.1, §1.2, and the
positional-coupling hazard in `resolve_parents` (parenting depends on
exact push order over a last-writer-wins simple-name map) is a
one-assertion catch. The frontend has two test files; one locks in the
nonconformant `satisfy X;` output. Recommended first test: parse the
domain libraries' ReliefValve example and assert the element tree,
spans against the real file, and the trace matrix — it would catch
§1.1, §1.2, §1.3, and half of §4 at once.

## 6. Recommended sequence

1. **Bump sysml-core to the v0.8.0 tag** (grammar conformance, 12 MB
   iOS savings, standalone_redefines, quoted names, metadata, checks,
   units, doc, variants — all at once, near-zero API risk).
2. **Fix the two span defects** (1-based convention end-to-end; parse
   per-file via `resolver::Project` instead of concatenation) — until
   then, editing with imports or multiple files open is unsafe.
3. **Replace the traceability matcher** with
   `resolver::traced_requirement_defs` + `query::trace_requirements`,
   and surface `query::evaluate_gate` (the CLI's gate semantics) in
   the dashboard.
4. **Delete the hand-rolled BOM engine** (route the BOM tab through
   `evaluate_rollup`), and pass `unit`/`conversion_warnings` through
   to the UI.
5. **Move editing onto `codegen/edit.rs`** (byte spans, overlap
   rejection, diff preview) and re-validate before save; make saves
   atomic (temp + rename).
6. **Adopt `view_render`** for view defs (send the rendered table over
   IPC) instead of view-evaluator.ts; keep the interconnection layout
   for diagram views.
7. **Fix the generated-SysML forms** (`analysis def`,
   `satisfy ... by ...;`, quoted short names, transition clause order)
   and re-check the emitter against the pilot.
8. **Replace the demo model** with a pilot-conformant one — ideally the
   relief-valve example from the domain libraries, which showcases
   views, uncertainty analysis, FMEA, and gates the moment those
   engines are wired in.
9. Make Tauri commands `async`, reuse the cached parse in analysis
   commands, and stop holding mutexes across `catch_unwind`.
10. Add the end-to-end fixture test (item 5 above) to CI.

Items 1–4 change user-visible numbers from wrong to right; everything
else is hardening and capability.
